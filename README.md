# Sigma Mate

Оркестрация агентов-сотрудников. Прототип: Ruby-обвязка запускает pi-агента
(developer), передаёт ему текстовый вопрос и печатает ответ.

## Требования

- Ruby 3.3+ (проверено на Ruby 4.0.2)
- `pi` на `PATH` (проверено на pi-coding-agent 1.0.0); задаётся текущей
  глобальной конфигурацией pi на машине - модель и провайдер в проекте
  не переопределяются

## Установка зависимостей

```bash
bundle install
```

Зависимости зафиксированы в `Gemfile.lock`.

## Запуск

Задать агенту вопрос и получить ответ:

```bash
bundle exec ruby bin/ask "Какой гем используется для связи с pi?"
```

Ответ агента печатается в stdout, после чего процесс завершается сам
с кодом 0.

Агент запускается через `pi --mode rpc` (гем [pi-agent-rb](https://github.com/chagel/pi-agent-rb)),
системный промпт сотрудника developer берётся из `agents/developer.md`,
рабочий каталог - корень проекта. Модель и провайдер - как настроено в
глобальной конфигурации pi.

Если pi недоступен или сессия упала, печатается понятное сообщение об ошибке
в stderr, процесс завершается с кодом 1 (код 2 - не задан вопрос).

## Сервис агента

`bin/serve` поднимает pi-сессию агента developer один раз и держит её
открытой, обслуживая HTTP-запросы до остановки (Ctrl-C или SIGTERM):

```bash
bundle exec ruby bin/serve [--host АДРЕС] [--port ПОРТ]
```

Адрес и порт - флаги `--host`/`--port` или переменные `SM_HOST`/`SM_PORT`,
по умолчанию `127.0.0.1:4567`; адрес и порт печатаются при старте.

### Шина сообщений (NATS)

Кроме HTTP, сервис слушает шину NATS: параметрами запуска передаются
идентификатор агента (его уникальный адрес в шине) и адрес ноды:

```bash
bundle exec ruby bin/serve --agent-id developer --nats-url nats://127.0.0.1:4222
```

Те же значения через переменные `SM_AGENT_ID` и `SM_NATS_URL`. С момента
старта сервис подписывается на очередь своего идентификатора (subject
совпадает с идентификатором) и печатает каждое входящее сообщение в свой
вывод:

```text
[шина] подписка на очередь developer поднята (nats://127.0.0.1:4222)
[шина] developer <- входящее сообщение (61 байт): живая проверка SGM-4: привет от шины
```

Смысл сообщений и формат ответов задаёт протокол поверх шины (SGM-5),
пока сервис только честно показывает полученное: subject, размер,
reply-адрес при наличии и payload целиком. Без идентификатора или адреса
шины подписка не поднимается: сервис печатает ошибку и продолжает работать
по HTTP. Обрыв связи с шиной не роняет сервис и не мешает HTTP-API:
потеря и восстановление видны в выводе (`[шина] шина недоступна ...`),
после возврата ноды подписка поднимается автоматически, приём
продолжается. HTTP-API работает и при поднятой подписке.

### Формат запроса и ответа

```bash
curl -s http://127.0.0.1:4567/ask \
  -H 'Content-Type: application/json' \
  -d '{"prompt": "Какой гем используется для связи с pi?"}'
```

Ответ - JSON:

- успешный прогон - `200 {"status":"ok","answer":"..."}`;
- запрос прерван новым - `200 {"status":"interrupted","detail":"..."}`
  (ответ приходит сразу, клиент не зависает);
- пустой промпт или битый JSON - `400 {"status":"error","detail":"..."}`;
- pi не поднялся или сессия упала - `503 {"status":"error","detail":"..."}`
  (сервис при этом остаётся живым).

Один запрос - один ответ того же запроса. Запросы обслуживаются по одному,
без параллельной обработки: один прогон в каждый момент. Если во время
прогона приходит новый запрос, сервис прерывает текущий прогон
(`session.abort`), прерванный клиент получает `interrupted`, и агент
отвечает на новый промпт в этой же сессии.

## Тесты

Автотесты запускают `bin/ask` и `bin/serve` против фейкового `pi` (заглушка
`spec/fake_pi.rb`, говорящая на JSONL-протоколе RPC, с задержкой ответа и
обработкой abort для сценариев прерывания) и слушателя шины против
фейкового NATS-сервера (`spec/fake_nats.rb`, текстовый протокол NATS:
INFO/CONNECT/PING/PONG/SUB/PUB/MSG), живой сети не требуется:

```bash
bundle exec rspec
```

## Структура

- `bin/ask` - CLI-обвязка: вопрос -> pi-агент -> ответ
- `bin/serve` - сервис агента: держит pi-сессию открытой, POST /ask,
  слушает шину NATS
- `lib/sigma_mate/` - `coordinator.rb` (одна сессия, прерывание, очередь
  из одного запроса), `service.rb` (HTTP-обвязка на WEBrick) и `bus.rb`
  (подписка на шину NATS: подключение, приём, журнал, переподключение)
- `agents/developer.md` - инструкции сотрудника developer
- `backlog/` - трекер задач (Backlog.md)
- `deploy/nats/` - конфигурация NATS-шины сообщений агентов
  (параметры и управление - `backlog/docs/doc-2 - Шина-сообщений-NATS.md`)
