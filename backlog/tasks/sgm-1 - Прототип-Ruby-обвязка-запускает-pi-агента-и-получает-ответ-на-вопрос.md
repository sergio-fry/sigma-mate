## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Нужен работающий каркас, на котором дальше строится оркестратор: Ruby-приложение запускает pi-агента, передаёт ему текстовый вопрос и показывает ответ. Это первая проверка связки Ruby и pi, пока без трекера, правил назначения и нескольких сотрудников: важно убедиться, что запуск и получение ответа вообще работают.

Агент - сотрудник developer из команды проекта. Запуск идёт через pi с той же глобальной конфигурацией, что настроена на машине сейчас, поэтому модель и провайдер в проекте не настраиваются и не переопределяются. Обвязку запуска берём готовую: гем pi-agent-rb (https://github.com/chagel/pi-agent-rb), приложение пишем на Ruby.

Похожую работу уже делает letsdo: он запускает pi отдельным процессом на каждую задачу. Здесь нужен другой режим - управляемая сессия, к которой позже появится API (чем агент занят, как вмешаться, что у него идёт не так). Поэтому pi-agent-rb и его RPC-режим важны как основа для следующих задач.

Вопрос задаётся при запуске, ответ печатается, процесс завершается сам. Поведение при недоступном pi тоже должно быть понятным: прототип должен честно падать с внятной ошибкой, а не молчать.
<!-- SECTION:DESCRIPTION:END -->

## Implementation Plan

<!-- SECTION:PLAN:BEGIN -->
1. Подключить гем pi-agent-rb (~> 1.1.0) через Gemfile, зафиксировать зависимости в Gemfile.lock (Ruby 4.0.2).
2. Написать CLI bin/ask: вопрос из ARGV, запуск pi --mode rpc через PiAgent.session с глобальной конфигурацией (модель/провайдер не переопределяются), системный промпт сотрудника developer из agents/developer.md через --append-system-prompt, cwd = корень проекта.
3. Ответ агента печатается в stdout, процесс завершается с кодом 0; gem закрывает транспорт, дочерних pi не остаётся.
4. Обработка ошибок: PiAgent::BinaryNotFoundError / TransportClosedError / CommandError и пустой вопрос -> понятное сообщение в stderr, код возврата != 0.
5. Автотест (RSpec) с фейковым pi-бинарником (PI_BIN на заглушку, говорящую на JSONL-протоколе RPC): проверка запуска, печати ответа и кода 0 без обращения к сети; плюс тест ошибки при недоступном pi.
6. README: установка зависимостей, запуск, запуск тестов.
7. Живой прогон на машине, запись факта в заметки задачи.
<!-- SECTION:PLAN:END -->

## Implementation Notes

<!-- SECTION:NOTES:BEGIN -->
Реализация: bin/ask (Ruby, гем pi-agent-rb 1.1.0) запускает pi --mode rpc с --append-system-prompt agents/developer.md и cwd=корень проекта; модель/провайдер из глобальной конфигурации pi, в проекте не настраиваются. Ответ печатается в stdout, exit 0; ошибки PiAgent (нет pi, умерла сессия, отклонена команда) -> понятное сообщение в stderr и код 1, пустой вопрос -> код 2. Автотесты RSpec (4 примера) гоняют bin/ask против фейкового pi (spec/fake_pi.rb, JSONL RPC-протокол) без сети; 3 прогона подряд - 0 failures. Особенность гема: pi ищется по имени на PATH, абсолютный путь в PI_BIN не работает - тесты кладут заглушку с именем pi в prepended-каталог PATH.

Живой прогон на этой машине (03.10.2026): 'bundle exec ruby bin/ask "Скажи одним предложением: какой агент ты и видишь ли ты инструкции сотрудника в своём промпте?"' -> ответ получен: агент представился developer, подтвердил видимость инструкций сотрудника; stdout=ответ, stderr пуст, exit=0, время ~8.5с; после завершения дочерних процессов pi не осталось (pgrep чист).
<!-- SECTION:NOTES:END -->
