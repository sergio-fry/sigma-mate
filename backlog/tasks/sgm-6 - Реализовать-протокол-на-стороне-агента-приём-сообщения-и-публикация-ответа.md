## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Первая половина реализации протокола (SGM-5): сторона агента. Агент принимает сообщение из своей очереди, обрабатывает его как задачу в той же сессии, что и HTTP-запросы, и публикует ответ отправителю с корреляцией на исходное сообщение. Сценарий проверки: отправитель кладёт сообщение в почтовый ящик агента и получает ответ, что работа готова, с результатом внутри.

Ошибки обработки и сообщения, которые агент не смог принять, не должны теряться молча: по протоколу отправитель получает понятный ответ или ошибку. Поведение занятого агента - по решению из SGM-5.
<!-- SECTION:DESCRIPTION:END -->

## Acceptance Criteria
<!-- AC:BEGIN -->
- [ ] #1 Сообщение, отправленное в очередь агента, приводит к обработке промпта в его сессии.
- [ ] #2 Ответ публикуется в шину и связан с исходным сообщением по корреляции из протокола.
- [ ] #3 Если обработка упала, отправитель получает ответ об ошибке, а не тишину.
- [ ] #4 Поведение агента, когда он уже занят работой, соответствует протоколу.
- [ ] #5 Состояние сессии не зависит от входа: задача, пришедшая из шины, видна в HTTP-API так же, как задача из HTTP-запроса.
<!-- AC:END -->

## Definition of Done
<!-- DOD:BEGIN -->
- [ ] #1 Живая проверка на реальной шине: сообщение опубликовано клиентом шины, ответ получен в inbox отправителя; команды и вывод записаны в отчёте.
- [ ] #2 Есть автотест на обработку входящего сообщения и публикацию ответа без живой шины.
- [ ] #3 Изменения закоммичены, документация проекта и правила агентов актуальны.
<!-- DOD:END -->
