## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Сервис агента (SGM-2) должен уметь принимать сообщения из шины, а не только отвечать на HTTP-запросы. При запуске сервису передаётся идентификатор агента в параметрах запуска: это уникальный адрес сотрудника в шине. Получив идентификатор, сервис с момента старта слушает соответствующую очередь и показывает входящие сообщения в своём выводе.

Пока делаем транспортную часть: подключение к NATS, выбор очереди по идентификатору, приём сообщений и журнал. Смысл сообщений и формат ответов задаёт протокол (SGM-5), поэтому здесь важно не потерять входящее сообщение и честно показать его в логе сервиса. HTTP-API из SGM-2 продолжает работать: сервис слушает и шину, и HTTP одновременно.

Адрес шины берётся из конфигурации или параметров запуска, а не из кода. Обрыв связи с шиной не должен ронять сервис и не должен ломать HTTP-API.
<!-- SECTION:DESCRIPTION:END -->

## Acceptance Criteria
<!-- AC:BEGIN -->
- [ ] #1 Идентификатор агента передаётся параметром запуска; без него сервис сообщает об ошибке и подписку не поднимает.
- [ ] #2 При старте сервис подключается к шине по адресу из конфигурации, адрес не зашит в код.
- [ ] #3 С момента запуска сервис слушает очередь своего идентификатора, и пришедшее сообщение видно в выводе сервиса.
- [ ] #4 Обрыв связи с шиной не роняет сервис и не мешает HTTP-API; после восстановления связи приём сообщений продолжается.
- [ ] #5 HTTP-API из SGM-2 работает и при поднятой подписке на шину.
<!-- AC:END -->

- [ ] #2 Есть автотест на подписку и приём сообщения без живой шины.
